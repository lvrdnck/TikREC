## Changes since published v0.10.0

- Configurable automatic-recording free-space reserve (1–1024 GiB, default 10) and bounded read-only storage health. Missing/unavailable storage and insufficient space block unattended admission. Checks do not reserve disk bytes, stop an in-flight capture or gate explicit manual starts; no disk-pressure deletion is introduced.
- Read-only immediate-session retention planning with creator protection, optional age policy (1–3650 days, **disabled when unset**), stable counts/sizes and conservative `needs_attention` classification. A plan is advisory and never authorizes deletion.
- Explicit **local Windows-only** deletion of one eligible session, after an exact UUID preview/confirmation and fresh authorization. Root/claim/volume identity, unchanged file bytes, policy, completed media, audit history, current jobs and cooperative writer ownership are rechecked. Retained artifacts/control files precede the final MP4; durable intent and completion records report what actually happened. No bulk, scheduled, background, HTTP or automatic retention operation exists.
- Supporting fixes already accepted in the storage base: immutable creator identity/legacy absence handling, coherent Windows writer-partial recovery proof, no-follow manifest/evidence handling, alias/race/chronology checks, serialized policy changes and root lifecycle leases across recording/finalization/recovery. Retention boundary fixes preserve the first failure, secondary teardown diagnostics and proven completion across output or cleanup failures. The full v0.10-to-base delta is retained, rather than reduced to the public command alone.

## Operator scope and compatibility

Windows is the sole supported recording/service runtime. Native destructive retention validation covers fixed-drive NTFS under the cooperative-filesystem boundary; it does not establish arbitrary-filesystem, hostile-process or power-loss guarantees. Redirected/reparse/symlink, network, unsupported or unprovable storage refuses destructive work. POSIX/macOS/Linux destructive retention refuses before lock/audit/media mutation; pre-existing remote-client/offline helpers and read-only planning remain available.

The two-slot service and existing bearer/bind/origin/request protections remain. Monitored creators and other service configuration are selected at startup. Finalization still occupies its recording worker/slot. The service exposes no deletion API. Manual/remote diagnostic raw capture remains explicitly opt-in and best effort; this release adds no automatic raw-copy preference.

**Excluded:** later #30 creator hot reload, #48 per-creator automatic raw-copy, and all #52 journal/capture-finalizer/HTTP/UUID-capability source. There is no `durable_finalization_v1`, `/sessions/UUID`, isolated finalizer catalog or optional UUID remote-status feature. Remote targeted stop remains the existing two-slot operation; remote status retains its historical singular semantics.

This is a release of a historical feature set, **not an upgrade or downgrade of the owner's newer development installation**. Do not replace/restart that installation, modify its editable environment or Gracie-only policy, or use its configuration, services, recordings or state to test this package. Strict schema-1 configuration rejects later unknown fields such as `automatic_raw_copy_creators`; schema equality alone is not compatibility. #52's schema-10 journal is unsupported here and must never be repointed, migrated or initialized over. Validate/install only in an independent environment with deliberately separate configuration/state and generated fixtures. No migration is included.

Retention excludes incomplete, ambiguous, unsafe, protected, unknown-creator/legacy and current durable-job-linked candidates. Raw/diagnostic/forensic evidence is not an ordinary eligible deletion target. Sharing a root with active cooperative writers blocks destructive retention; changing evidence can invalidate the entire advisory scan. Confirm one UUID only after a fresh preview. If intent/removal is uncertain or incomplete, preserve remaining artifacts/audit and stop; there is no automatic retry, resume, quarantine cleanup or repair. A known durable completed event retains COMPLETE/0 even if later reporting/cleanup fails. See [RETENTION_CLI.md](https://github.com/lvrdnck/TikREC/blob/2fe6354aa508d53ce3a3452ce08743d97400fe73/RETENTION_CLI.md) and [SPEC.md](https://github.com/lvrdnck/TikREC/blob/2fe6354aa508d53ce3a3452ce08743d97400fe73/SPEC.md) for exact exit and safety contracts.
