## Continuous operating policy

Path identity checks use fresh no-follow metadata for the target and every ancestor, plus a separate known-target revalidation after traversal. Related facts share that observation only within the call; no cross-call cache. Missing/non-directory ancestry, dangling links/junctions, reparse points, file hardlinks and uncertain metadata refuse. Both state/media checks and both physical free-space queries still run at every original policy boundary; native pins remain independent authority. [Scoped correction and measured limits](ISSUE_52_THROUGHPUT_MEASUREMENT.md). Existing homes bound to a previous source fingerprint are not upgraded or migrated.

Configured reserve R defaults to **10 GiB** (existing configuration range 1–1024). Fresh physical free-space observations cover both state and media before admission, capture writes and finalization boundaries, and independently in the supervisor while no HTTP request arrives. Admission requires **R+4 GiB**; unclaimed finalization requires **R+2 GiB+16 MiB**; captures stop at **R+0.5 GiB** or unknown storage. The 16-MiB pad defers before claiming when the minimum writer budget is unavailable. Pressure stops from the source and supervisor share the original authority lock; an existing stop or closed/closing binding is never mutated again. At the finalizer floor only the exact owned attempt is cancelled while captures above their floor continue. Unknown catalog/storage stops original captures cooperatively and preserves evidence. Space restoration resumes only unclaimed FIFO work. No eviction, deletion, refund or guessed byte reservation.

Physical occupancy already accounts once for retained parts/raw/arrivals, candidate/failed scratch, final outputs and catalog/control growth; moving a candidate changes its name rather than counting it twice. No history scan or unspent encoder reservation gates capture. Each writer receives a fresh budget `min(free_state, free_media) - R - 2 GiB`, minimum 16 MiB, in its original durable launch recipe. A candidate within `min(16 MiB, budget/8)` of that budget is sealed only for exact original cleanup, refused before validation/publication, and reports `candidate_budget_needs_attention`. Zero FFmpeg exit is insufficient. Its unit remains pinned. Default/pilot byte-refusal behavior stays compatible.

The additional admission margin leaves 2 GiB above the finalizer baseline for simultaneous raw/parts growth and catalog/cleanup writes; the writer budget leaves that baseline free rather than pre-reserving it. The smaller capture margin supports cooperative evidence closure after finalization has stopped. These are conservative engineering defaults tested under bounded generated load, not bitrate-derived guarantees. Raising configured reserve preserves every additional margin.

Observations normally run every **0.1 seconds**, plus a check before each **64 KiB** read/write and yielded FLV tag; transport stop-aware timeout is **5 seconds**. Existing SQLite waits can take **1 second**, exact child cancellation up to **5 seconds**, and filesystem/fsync/native operations can stall. These are cooperative margins, **not a hard quota or a guaranteed wall-clock maximum** under storage stalls or rapid unrelated disk consumption. FFmpeg `-fs` can overshoot. Independent supervisor checks remain active during worker hashing/encoding. No unattended-duration guarantee follows from these tests.

Two captures, one finalizer, eight **outstanding** units remain. No 120-second, 64-MiB ingress, 256-MiB fixed candidate, 900-second service lifetime or eight-completion limit. One capture still bounds metadata at **512 source connections, 1024 configuration tags, 1024 backward media-clock observations**; overflow refuses truthfully with unfinished ownership, never drops data. AVC positive dimensions long edge ≤1920/short edge ≤1080, configuration payload ≤4096 bytes and tag payload ≤1 MiB preserve a bounded decoder/parser envelope. The existing 24-bit FLV parser may buffer up to roughly 16 MiB before rejecting an oversized tag. Geometry/quality/timing are not transformed to fit pressure.

Completed metadata/media remain on disk subject to fresh-space policy, with no retention execution. Existing retention planning refuses journal artifact inventories; generated read-only proof verifies no eligible artifacts and unchanged bytes. Configuration and committed automation documents each have a 1-MiB bound. Automation save refuses overflow before replacement using its existing typed state-error/acknowledgement path; it never drops consumed creators to fit or recreates a lost known file. Active registries/projections are bounded by slots/units; known-retired native references and completed attempts are pruned, unknown originals retained. Addressed UUID history is indexed and paged, never loaded wholesale for normal supervision. Four diagnostic ring segments each ≤1 MiB and each receipt ≤16 KiB bound disk logs; per-capture metadata bounds also bound owner/control evidence. Console emits startup/ready/shutdown/exit or fixed failure categories, not continuous observations.

## Ownership and shutdown

Startup logs actual loaded source path/fingerprint/revision, interpreter/SQLite/PID, explicit config hash and checked executable paths/version/hash before worker/monitor work. Listener binding precedes work; catalog authority precedes logs. Bounded sanitized UUID lifecycle/storage/stop observations and actual shutdown/exit receipts omit secrets, signed URLs and arbitrary exception text. Diagnostic failure stops supervision through original cleanup; it never resends accepted starts.

Ctrl+C or local `control.json` `{operation: canonical fresh UUID, command: shutdown}` fences new starts, joins monitor/requests, cooperatively stops original captures and allows existing bounded finalizer shutdown grace. It can leave unclaimed queued units for known reopen. Exit **0** means confirmed owner retirement, not empty backlog; **2** means startup/supervision failure; **3** means attention/diagnostic stop despite confirmed retirement. Incomplete retirement keeps the same supervisor and owners alive. Only a new explicit `cleanup` nonce requests another cleanup attempt. Never kill a PID, guess native handles, force completion or restart around uncertainty.
